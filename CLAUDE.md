# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Overview

This repository contains two main projects:

1. **Original HyperNetworks for CIFAR-10** - PyTorch implementation of HyperNetworks (Ha et al., ICLR 2017) for ResNet architectures
2. **CompressARC** - An ARC-AGI puzzle solver that uses compression-based intelligence without pretraining, datasets, or search

The repository is actively being developed to implement hypernetworks for the CompressARC architecture.

## Commands

### Training

**Original HyperNetworks (CIFAR-10):**
```bash
python train_hyper.py                    # Train HyperNetwork ResNet on CIFAR-10
python train_hyper.py --resume           # Resume from checkpoint
```

**CompressARC (ARC-AGI):**
```bash
python run.py                      # Run multi-GPU parallel solver on ARC-AGI puzzles
python solve_task.py              # Solve individual task (used internally by run.py)

```

## Architecture Overview

### HyperNetworks (CIFAR-10)

**Core Concept:** A small "hypernetwork" generates weights for a larger "primary network" dynamically.

**Key Components:**
- **HyperNetwork** (`hypernetwork_modules.py`): Takes z-vectors as input, outputs convolutional kernels
- **Embedding** (`primary_net.py`): Maintains learnable z-vectors for each layer
- **PrimaryNetwork** (`primary_net.py`): ResNet-18 architecture where conv weights are generated by HyperNetwork
- **ResNetBlock** (`resnet_blocks.py`): Modified residual blocks accepting dynamic weights

**Architecture Flow:**
1. Each ResNet layer has 2 embedding vectors (z₁, z₂) of dimension 64
2. HyperNetwork transforms z → convolutional weights dynamically
3. ResNet forward pass uses generated weights for convolutions
4. Massive parameter reduction: ~25k params vs ~11M (440× compression)

### CompressARC (ARC-AGI)

**Core Concept:** Solve puzzles by finding minimal-bit compressed representations using VAE-like architecture.

**Key Components:**
- **MultiTensor System** (`multitensor_systems.py`): Manages tensors with dimensions [example, color, direction, height, width, channel]
- **ARCCompressor** (`arc_compressor.py`): VAE decoder architecture with equivariance properties
- **Task** (`pre_processing.py`): Preprocesses ARC-AGI puzzles into multitensor format
- **Layers** (`layers.py`): Equivariant operations (decoding, softmax, cummax, shift, communication)

**Architecture Flow:**
1. Sample z ~ N(μ, Σ) from learned distribution
2. Decode through equivariant layers (4× blocks of: share_up → softmax → directional ops → nonlinear → share_down)
3. Linear heads produce pixel logits + grid masks
4. Optimize θ, μ, Σ to minimize: KL(z||N(0,1)) + CrossEntropy(predictions, observed grids)
5. Most frequent output during training = answer

**Equivariances:** Network is symmetric to:
- Example reordering
- Color permutations
- Spatial rotations/reflections (via weight tying and directional layers)

### Multitensor System

**Critical Design Pattern:**
- Data flows as "multitensors" - collections of up to 18 tensors with shapes that are subsets of [example, color, direction, height, width, channel]
- Each layer operates on all tensors in parallel, treating non-channel dims as batch dims
- Enables equivariant processing: transforming input transforms output identically

**Dimensions:**
- `example`: Number of input-output pairs in puzzle + 1 (includes test case)
- `color`: Unique colors in puzzle (excluding black)
- `direction`: 8 (4 cardinal + 4 diagonal)
- `height`, `width`: Determined during preprocessing based on grid sizes
- `channel`: Always present; size varies by layer (8 or 16 in residual stream)

## Development Notes

### Terminology (from COMPRESSARC.md)
- `dims`: Length-5 list [example, color, direction, height, width] indicating dimension presence
- `axis`: Index position of a dimension in actual tensor
- `x`, `y`: Refer to height, width dimensions respectively
- Decorators:
  - `@multitensor_systems.multify`: Apply function to each tensor in multitensor
  - `@layers.add_residual`: Add residual connection with projections
  - `@layers.only_do_for_certain_shapes(*shapes)`: Conditionally apply based on dims

### Memory Considerations
- See `GPU_Memory_Guide.md` for comprehensive GPU memory analysis
- Activations dominate memory (not parameters), even with 440× parameter compression
- HyperNetworks save ~2.5× total training memory, 440× storage/inference memory
- Batch size is primary memory control

### Hypernetwork Development (In Progress)
The repository is being extended to implement hypernetworks for CompressARC using a **meta-learning approach**:

**Two Hypernetwork Paradigms:**
1. **CIFAR-10 (Layer Embeddings)**: Fixed embeddings per layer → single network for all data → zero-shot inference
2. **ARC (Task Embeddings)**: Separate embedding per task → different network per task → test-time adaptation required

**ARC Meta-Learning Strategy:**
- **Meta-training**: Train shared hypernetwork on all possible training tasks, learning good weight generation patterns
- **Inference on new task**:
  - Initialize random task embedding
  - Generate initial weights via trained hypernetwork (structured, better than random)
  - Optimize embedding via test-time adaptation using task's training examples
  - Hypernetwork constrains search space and accelerates convergence

**Key Differences from CIFAR-10:**
- Embeddings represent **tasks** (not layers) and are **NOT shared** between different tasks
- Each task is a completely different problem requiring task-specific weights
- Test-time training unavoidable (cannot do zero-shot on novel ARC tasks)

**Benefits over Original CompressARC:**
- Fewer parameters to optimize during inference (embedding only vs all weights)
- Better initialization from trained hypernetwork (learned inductive biases)
- Faster convergence due to structured weight space
- Improved final accuracy from meta-learned priors

**Implementation Files:**
- `hypernetwork_arc.py` - Generates ARCCompressor weights from embeddings + task metadata
- `arc_primary_net.py` - End-to-end model (hypernetwork + task embeddings + architecture)
- `train_arc_hyper.py` - Single-task training with hypernetwork
- `run_arc_hyper.py` - Multi-task meta-training across 400 puzzles

See `COMPRESSARC.md` section "Joint Compression via Weight Sharing Between Puzzles" and `README.md` (ARC hypernetworks) for details. Original CIFAR-10 implementation is documented in `README_CIFAR10.md`.

### Training Strategy (CompressARC)
- No pretraining - random initialization
- Per-puzzle optimization during inference
- 2000 iterations, Adam optimizer (lr=0.02, β₁=0.5, β₂=0.9)
- Reconstruction heavily weighted (10×) over KL initially
- Cosine annealing LR schedule
- Solution = most frequent network output during training

### Multiprocessing Architecture (run.py)
- Deterministic task scheduling via memory-based ordering
- GPU quota system with 1.2× safety margin for backprop variance
- Task-specific seeding: `seed = hash(task_name) % 2³²`
- 256MB memory quantization for stable task ordering
